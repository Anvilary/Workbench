# WebAuthn security keys

Electron does not provide a platform WebAuthn authenticator on Linux. Workbench bridges `navigator.credentials.get()` in the ChatGPT session to a hardware FIDO2 key through the libfido2 command-line tools (`fido2-token`, `fido2-assert`). Source: `packages/desktop/src/security/webauthn-ipc.mjs` and `packages/desktop/src/security/webauthn/`.

## Scope

- Assertions (sign-in) only. Registering new credentials is not bridged.
- Only the main frame of a view in the ChatGPT partition may use the bridge, and only from an allowed origin: `https://chatgpt.com`, `https://auth.openai.com`, `https://auth0.openai.com`, `https://openai.com`. `WORKBENCH_WEBAUTHN_EXTRA_ORIGINS` (comma-separated; legacy `WORKBENCH_WEBAUTHN_EXTRA_ORIGINS`) adds origins for testing.
- One request can be in flight at a time.

## Validation

- The requested `rpId` must be a registrable suffix of the requesting origin and must not contain a scheme, port, user info, path or whitespace.
- Assertion options are validated (timeout bounded to 600 seconds). The client data is generated by the desktop from the challenge and the verified origin, never taken from the page.
- The returned authenticator data is checked against the SHA-256 of the `rpId`, and user verification is enforced when requested.

## User interaction

A trusted native dialog (not page content) shows the requesting origin, asks for the PIN and reports progress. The PIN is validated, passed to the tool on stdin and never logged or kept. The backend iterates connected devices and resident credentials with bounded attempts, runs each tool in its own process group with a timeout, and cancels cleanly when the dialog or page goes away. Errors map to standard WebAuthn error names (`NotAllowedError`, `SecurityError`).

## Requirements

Install the libfido2 tools (`fido2-tools` on Ubuntu). Without them the bridge reports itself unavailable and the page falls back to its other sign-in methods.
